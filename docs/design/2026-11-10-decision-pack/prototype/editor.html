Try this
  1. In Ingredients, click at the end of “pinch of salt”, press Enter and type # Spice. The line grows and the # goes soft as you type the name.
  2. Put the caret in the middle of a line, open Insert and choose Section heading. A new line appears under it with “Section name” selected; type over it.
  3. Copy these three lines from another app and paste them into Method:
    # Filling / Mix the sugar and spices. / Spread to the edges.
  4. Press Cmd+Z (Ctrl+Z) three times, then Shift+Cmd+Z. Typing, the inserted heading and the paste undo and redo like any text box.
  5. Select from the middle of the Dough list down past # Filling, copy, and paste it at the end of Method. Same lines, same styling.
  6. Type a bare # on its own line, empty the Title, and press Save.
  7. Open “What would be sent” at the bottom: it is the plain text the server receives, and how it splits.

How this works, and its limits

    
    
      
  • Approach: each box is a contenteditable div with one block per line. After each input the script sets a class on a line, and one CSS variable (where the # ends), only when they change. It never rewrites text, so the caret, autocorrect and the browser's own undo stack are left alone. The soft # is a two-colour background clipped to the text, because ::first-letter colours “# D” in both engines and the CSS Highlight API did not paint in the WebKit build here. Paste goes in as plain text through insertText, so it lands on the same undo stack.
    • 
      
  • Verified, 9 Nov, in Playwright Chromium and WebKit (Safari 27.2 engine), 50 and 46 scripted checks, all passing: typing # Spice styles the line (larger, 600, # measured); Insert → Section heading under a mid-line caret adds a line below with “Section name” selected, and typing replaces it; a pasted multi-line block with a # Drizzle line splits the same way and arrives as plain text with no HTML; typed, inserted and pasted headings send identical text and parse identically; Cmd+Z undoes typing in runs (as a textarea does), the insert in one step and a paste in one step, and Shift+Cmd+Z redoes; Backspace merging a line into a heading undoes cleanly; Cmd+B does nothing; boxes grow; Save shows the shipped messages with aria-invalid, counts down as fields are fixed, focuses the first field in error, keeps everything on “server unreachable”, then saves as v4.
    • 
      
  • Verified in Chromium only: real Cmd+C across a heading puts plain lines on the clipboard, and Cmd+V of them styles the heading. Shift+Tab from a box reaches Insert, Enter and Space open it, and Tab then Enter inserts. In WebKit the same works with Option+Tab, as Safari skips buttons on Tab by default.
    • 
      
  • Not verified: real Safari on a Mac or iPhone, Firefox, iOS and Android autocorrect, dictation and the text-selection handles, a screen reader. WebKit paste was checked with a synthetic paste event, not the system clipboard.
    • 
      
  • Known limits: dragging text inside a box copies rather than moves it (drops are forced to plain text). In Chrome, merging a line into a heading leaves a hidden styled span in the box (made inert by CSS, never sent). Redraws wait one task after each keystroke, because a same-moment DOM change ends Chrome's undo run. Photo, Tags and Cancel are pictures here. The shipped textarea cannot vary size by line, so shipping A means this box replaces it.
