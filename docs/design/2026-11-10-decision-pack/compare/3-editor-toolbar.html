Editor toolbar placement and live heading presentation

Same grouped buns recipe in both. Both keep plain-text # Dough headings with the # visible in Ink 3, and both insert # Section name with the name selected. Each frame opens at Ingredients; scroll inside it for the rest of the form. What differs is where Insert lives and how a heading line looks while editing. Try A for real in the interactive prototype.

A · Insert above each box, headings larger

B · One pinned Insert bar, headings heavier with a clay rule

Decide

What changes

A puts a folded “Insert” beside each box's label and draws a named heading line in Bitter 600, one step larger. B pins one Insert bar to the top of the form that acts on whichever box has focus, and keeps headings body size, heavier, marked by a 2px clay rule.

Why it matters

Insert is how someone who has never seen # finds sections, so it must sit where the typing happens. The heading's look is the only live proof that a line became a group before Save.

Recommendation: A

The control sits next to the box it changes, with no hidden “which box?” rule, and it folds away for the many recipes that never need it. Larger Bitter headings match the group names on the recipe page, so the editor previews the result.

Downside of A

Two Insert controls to discover, and a size change is a small jump as the first letter of a name is typed. The larger line also needs the contenteditable box; a plain textarea cannot do it.

Downside of B

A bar that targets “the focused box” loses its target when focus moves to the bar itself, which is confusing on a phone keyboard and for screen readers. The clay rule spends clay on a non-text mark, against Clay Is Text, and body-size headings read less like the page they become.
