# One Save, Versioned Formulation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One "Save changes" on the edit page writes settings and, only when the formulation changed, a new version that carries its own title, description, servings, times, ingredients and steps; stale tabs get a 409, failed saves keep the draft.

**Architecture:** `recipe_versions` becomes the owner of the formulation; `recipes` keeps five maintained copies for search and cards plus an `editRevision` counter. A pure `formulation.ts` decides "changed". One `?/save` action: validate, upload photo, then a short transaction that locks the recipe row, checks the revision, and writes. Readers (recipe page, diff, fork, seed) switch to the version's fields.

**Tech Stack:** SvelteKit 2, Svelte 5 runes, TypeScript strict, Drizzle + Postgres (Supabase), zod 4, Vitest, Playwright, Supabase Storage.

**Spec:** `docs/superpowers/specs/2026-10-23-one-save-design.md`

## Global Constraints

- Pre-production: no backfill, no legacy readers. Migration may delete existing recipe rows; local and hosted get reseeded.
- Schema changes edit `src/lib/server/db/schema.ts` and add a hand-written SQL migration in `supabase/migrations/` in the same commit. Never `drizzle-kit push`.
- Store only what cannot be derived, except the five copies on `recipes` which the spec names and comments.
- `quantity` never `amount`; literal unions not enums; fixtures from `src/lib/recipes/fixtures.ts`; `vi.hoisted()` for mocks used inside `vi.mock()`.
- Shape changes are a vertical slice: `svelte-check` is green at the end of every task.
- Run `pnpm test:unit` before every commit. Repo files use tabs. No `Co-Authored-By` lines.
- Ownership rule: after every write path, `recipes.title/description/servings/prepTimeMinutes/cookTimeMinutes` equal the latest version's values.
- 409 message, verbatim: `This recipe was changed in another tab. Reload to see the latest version, then reapply your edits.`
- Generated commit message: `Updated ` + changed groups joined with `, ` in the order title, description, servings, times, ingredients, steps, so `Updated servings, ingredients`, never the reverse.

## Review Focus

Inputs the spec implies but did not list a test for. Each has its test in the owning task.

1. A tag list with a duplicate or differently cased name (`Dessert`, `dessert`) must not count as a settings change against the stored set. Task 8.
2. Title changed only by surrounding whitespace, or description blanked from `null` to `""`, must not create a version. Task 2.
3. A `removeImage` flag sent when the recipe has no image must be a no-op, not a settings change. Task 8.
4. `editRevision` submitted as a non-integer string (`""`, `abc`) must be rejected as 400, never treated as 0 and matched. Task 8.
5. A version with `servings: 0` stored by an older seed cannot exist (validation floors at 1), but `prepTimeMinutes: 0` can: `diffMeta` and `VersionDiff` must show `0`, not treat it as missing. Task 5.
