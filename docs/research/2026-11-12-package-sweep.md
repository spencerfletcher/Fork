# Package sweep: hand-built code against packages, and packages for the roadmap

12 Nov 2026. Research feeding `docs/product/` (mainly ROADMAP.md P1 to P5). Nothing here is decided: every adoption is Spencer's call, and each line below is a recommendation.

Method: each hand-built area was sized with `wc -l` and its tests counted from the `it(`/`test(` calls in the files beside it. Package facts come from `npm view <pkg> version time dist.unpackedSize dependencies license`, run live on 12 Nov 2026. "Last release" is the publish date of the current version. Where a README decided the verdict, it was read on GitHub. Anything not checked is marked **unverified**.

## 1. Summary

- **Adopt now, ranked:** (1) move `parse-ingredient` from its exact pin at 3.0.0 to 3.2.0. It is already a dependency. 3.2.0 hardens the parser against slow pathological input, the reason `src/lib/recipes/limits.ts` caps lines at 300 characters, and 3.1.0 reads "(15 oz) can", which is close to the acceptance fixture "2 × 400 g cans". (2) `pluralize`, already approved, for free-text yield nouns only. Nothing else is worth adopting now.
- **Adopt when the feature is built:** `fflate` (Paprika import, photo zip in export), `htmlparser2` plus `ipaddr.js` (URL import: read JSON-LD and microdata, block private addresses), `@cooklang/cooklang` (Cooklang import and export, the official parser), `@sentry/sveltekit` or nothing (error reporting at public launch), `@faker-js/faker` as a dev-only option for the varied seed.
- **Keep ours:** quantity scaling and unit conversion, duration parsing, image sniffing and metadata stripping, rate limiting, form validation (zod is already in), diffing (`diff` is already in), slugs, highlighting, Markdown export, JSON-LD, sitemap, time zones, drafts, the database pool, and the UI primitives (Dropdown, ChoiceSelect, the picker, sheets).
- **Platform does it:** wake lock, notifications and timers (browser APIs), the PWA (SvelteKit's `$service-worker` plus the existing `static/manifest.webmanifest`), private photos (Supabase signed URLs), staging (a second Supabase project plus Netlify branch deploys), mail (Supabase SMTP for auth, a provider's HTTP API through `fetch` for notifications).
- **Posture:** 7 runtime dependencies (`package.json`), each doing work that is large or subtle: `diff`, `parse-ingredient`, `zod`, Drizzle, `postgres` and the two Supabase packages. The hand-built pieces are small, well tested and specific to recipes. Generic packages fit them worse. The real gaps are format and security work that has not been built yet (zip, HTML parsing, SSRF, Cooklang).

## 4. Risks and things not verified

- `time.modified` in the registry can mean a metadata edit, so last-release dates were taken from `npm view <pkg> time` for the shortlist (parse-ingredient, fflate, ipaddr.js, htmlparser2, schema-dts, both Cooklang packages, faker, request-filtering-agent, bits-ui, sanitize-html, melt, pluralize). Other dates in the tables are `time.modified` and may be later than the last real release.
- Unpacked size is not bundle size. Bundle sizes (bundlephobia) were not checked; the fflate and valibot per-function figures are their READMEs' claims.
- The parse-ingredient upgrade was not run here (this sweep ran no tests). Its changelog lists no breaking changes after 3.0.0, but improvements to the parser change what it reads, which can change scale and convert output. Run the full unit suite after the bump.
- Not checked: the Paprika archive format, `@cooklang/cooklang` WASM on Netlify functions and its bundle size, rate-limiter-flexible with `postgres.js`, whether request-filtering-agent re-checks addresses after redirects, the Anthropic SDK's server bundle size, and `date-fns-tz` (not looked up).
- `fieldErrors.svelte.ts` has no test file of its own; whether the editor tests cover it was not checked.
- Netlify's own image transforms were not evaluated for the photo pipeline. They would not replace metadata stripping, since the stored originals are what get served.
